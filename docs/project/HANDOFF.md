## Поточний стан

Версія **2.5.0** на `master`. Це переписаний Steam Desktop Authenticator, оригінальний код SDA використовувався лише як референс.

Репозиторій на GitHub **публічний**. Сюди не можна записувати локальні шляхи, хости, назви ключів, email чи будь-які дані акаунтів. Налаштування remote-ів живе лише в локальному `.git/config`. Тест `RepoConsistencyTests` падає, якщо в репозиторій потрапить maFile, `vault.json`, архів або приватний ключ.

Що є:
- ядро `Arcline.SteamGuard`, CLI `arcline-sda`, GUI на Avalonia 11;
- платформа .NET 10, цілі — Windows і Linux;
- виправлення SDA #1111 (trade protection);
- maFiles зашифровані за замовчуванням;
- експорт і імпорт, міграція сховища між ПК, імпорт старої папки SDA;
- автопідтвердження окремо для кожного акаунта, трей, автозапуск, опційне авторозблокування, очищення даних.

Усе, що програма пише поза своєю папкою, перелічено в `Platform/AppPaths`. Додаючи новий такий шлях, оновіть `Cleanup` і README («What is stored where»).

Тести: 53 юніт-тести ядра і 10 headless UI-тестів. Усі проходять, CI ганяє їх на Windows і Ubuntu.

Опубліковані релізи: v2.2.0–v2.4.0. Версію 2.5.0 закомічено, але тег не відправлено.

**Перевірено на реальному акаунті (2026-11-19, v2.4.0):** прив'язка нового автентифікатора з кодом із пошти.

SDK встановлено локально: `.dotnet\dotnet.exe` (у git не потрапляє). Збірка й тести: `.\.dotnet\dotnet.exe test EAArclineSDA.slnx`.

**Ще не перевірено на реальному акаунті Steam:** підтвердження й acknowledge, перенесення автентифікатора через SMS, видалення автентифікатора. GUI на Linux не запускався, тож трей, автозапуск і `secret-tool` там теж не перевірені; перевірено лише збірку під linux-x64.

## Наступні кроки

1. Перший прогін на одному реальному акаунті: імпорт його maFile → список підтвердження → accept трейду. Перевірити, що acknowledge спрацював, а токени зберігаються після рестарту.
2. Запустити GUI на Linux і перевірити трей, діалоги файлів та права `600` на файли сховища.
3. Розібрати пункти з [ROADMAP.md](ROADMAP.md).

## Правила, які легко порушити

- GUI не тестувати через SendKeys чи глобальні натискання клавіш, бо вони потрапляють у чужі вікна. Тільки `tests/Arcline.SDA.Desktop.Tests` (Avalonia.Headless).
- Нові NuGet-пакети брати лише у версіях, старших за 2 тижні.

## Журнал сесій

### 2026-11-17

- Проаналізовано старий SDA, переписано з нуля (ядро, CLI, GUI), виправлено #1111, введено формат `arcline-mafile` v1.
- Додано резервну копію, відновлення та злиття сховищ для переїзду між ПК. Ініціалізовано git на `master`, задокументовано 2.0.0.
- Налаштовано push у два remote-и одночасно. Вийшла 2.1.0: вибір, фільтр, масові дії та режим «All accounts» для підтверджень.
- 2.2.0: репозиторій підготовлено до публічного доступу (MIT, notices, перевірка на секрети, автор комітів переписаний на noreply). Додано CI і релізи з готовими архівами для Windows та Linux, README англійською.

### 2026-11-18

- 2.3.0: окреме автопідтвердження трейдів, продажу (лістинги на маркеті) і покупок (тип 12). Інші типи не підтверджуються автоматично ніколи. Правило вибору — `VaultSettings.ShouldAutoConfirm`.

### 2026-11-19

- Перший реальний тест користувача: програма падала після введення коду з пошти. Причина з журналу подій Windows: Steam рве простійне CM-з'єднання, поки людина шукає код, і далі летить `AsyncJobFailedException`.
- 2.4.0: `SteamLoginService` перед відправкою коду відновлює з'єднання, а при збої відправляє код повторно. Додано глобальний обробник помилок із логом у `ArclineSDA/logs`. Якщо автентифікатор уже є, його можна перенести через SMS (`RemoveAuthenticatorViaChallengeStart/Continue`).
- Відновлення з'єднання при вході та саме перенесення ще не перевірені на справжньому Steam: SteamKit2 не мокається, а перенесення покрите лише тестами з фейковим HTTP.
- 2.5.0: автопідтвердження тепер задається для кожного акаунта окремо (старі глобальні перемикачі мігруються); трей, автозапуск, опційне авторозблокування (DPAPI / secret-tool); пункт «Remove app data» і `arcline-sda cleanup`. Релізні збірки більше нічого не розпаковують у тимчасові теки: native-бібліотеки лежать поруч з exe.
