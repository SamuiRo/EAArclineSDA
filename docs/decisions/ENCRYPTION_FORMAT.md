# Власний самодостатній конверт: AES-256-GCM + PBKDF2-SHA256

**Status:** Accepted
**Date:** 2026-11-17

## Context

Старий SDA шифрував maFile через PBKDF2-SHA1 (50k) і AES-CBC. Сіль та IV зберігались у `manifest.json`, тому окремий файл не можна було розшифрувати в іншій програмі. Шифрування було вимкнене за замовчуванням.

Вимоги власника:
- шифрування за замовчуванням;
- робота на Windows і Linux;
- разовий перенос maFile у власні програми;
- переїзд між ПК.

## Decision

- Кожен файл — JSON-конверт `arcline-mafile` v1: AES-256-GCM, ключ через PBKDF2-HMAC-SHA256 на 600 000 ітерацій, сіль 16 байт, nonce 12 байт.
- Заголовок (`steamid`, `account_name`, параметри KDF) входить в AAD.
- Режиму без шифрування немає. Plaintext видається лише явним експортом.

## Consequences

- Розшифрувати можна будь-якою мовою стандартними примітивами: .NET BCL, Python `hashlib` + `cryptography`, Node `crypto`. Окремий файл не залежить від сховища.

Чому відкинуто альтернативи:

| Альтернатива | Чому програла |
|---|---|
| **Windows DPAPI** | Не працює на Linux, прив'язує дані до ПК |
| **Argon2id** | Сильніший проти GPU-перебору, але немає в BCL і в stdlib більшості мов, тож кожній програмі-споживачу знадобилась би окрема залежність. Лишається кандидатом для формату v2 |
| **age / scrypt** | Немає зрілої .NET-реалізації |
| **Залишити формат SDA** | Немає автентифікації, і сіль потрібно брати з окремого файлу |

- Стійкість повністю залежить від пароля, бо PBKDF2 лише сповільнює перебір. Тому мінімальна довжина пароля — 8 символів, а README радить фразу.
